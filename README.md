# 獅子編み検索 ver2

企画のドラフトを渡すと、似た過去企画（原文）と、そこからつながるシステム・法令・担当者を返すアプリ。
似た企画から線をたどるので、ドラフトに書かれていないシステムや担当者まで出てくる。次に誰と調整するかを表で読める。

資料はすべて架空のサンプル（銀行の商品企画という設定）。実在の企画・人物ではない。

## 全体の作り

流れは2本で、つながっているのは DB だけ。

- しまう: 資料を読む → 企画書の文章から点と線を抜く（台帳の表はそのまま） → DB にしまう
- 探す: ドラフトを受け取る → 似た企画を探して線をたどる → 表と絵で返す

Claude API を呼ぶのは「しまう」のときだけ。「探す」は API を呼ばない。

## ファイル

| ファイル | 役割 |
|---|---|
| `app.py` | 画面（Streamlit）。ドラフトを受け取り、結果を出す |
| `graph.py` | 似た企画を探し、線をたどり、表の形にまとめる |
| `ranking_v2.py` | TF-IDF で、似ている順に並べる |
| `zu.py` | たどった道を絵にする |
| `loader.py` | `data/` の資料を読む |
| `extract.py` | 企画書の文章から点と線を抜く（API を呼ぶ） |
| `database.py` | DB（`shishiami.db`）に書く・読む |
| `shimau.py` | loader → extract → database を順に呼ぶ |
| `llm.py` | Claude API を呼ぶ入口。キーを読む |
| `data/kikaku/` | 過去の企画書 12 件（文章） |
| `data/daichou.csv` | システム台帳（表）。システム名・別名・担当者・部署・稼働の決まり |
| `data/draft_sample.md` | 試し用のドラフト |
| `shishiami.db` | 読み込み済みの DB。これがあるので「資料を読み込む」を押さなくても探せる |

## 自分のパソコンで動かす

Python 3.11 で確認している。

```bash
pip install -r requirements.txt
```

```bash
streamlit run app.py
```

画面が開いたら「サンプルのドラフトを入れる」→「探す」を押す。ここまではキーが要らない。

「資料を読み込む」を使うときだけ、`.env.example` を `.env` という名前で写し、`ANTHROPIC_API_KEY=` の右に自分のキーを書く。
キーは Claude Console で作る。スコープは「組織」ではなくワークスペースを選ぶ（組織のキーは通らない）。
`.env` は `.gitignore` に入れてあるので、リポジトリには上がらない。`.env.example` にはキーを書かない。

## 知っておくこと

- 「資料を読み込む」は企画書の件数ぶん（いまは12回）API を呼ぶ。料金はキーの持ち主にかかる。
- API には、過去企画書の本文と、台帳のシステム名・別名が送られる。本物の資料を `data/` に入れる前に、社外に出してよいかを決める。
- 「DB を空にする」を押すと、キーが無い環境では戻せない（「資料を読み込む」で入れ直すしかない）。
- 点の種類（法令・システム）と線の種類（関わる・使う）は `extract.py` の上のほうで決めている。担当者とシステムの線は、台帳の表から `database.py` が作る。
- Excel で `data/daichou.csv` を直すときは「CSV UTF-8（コンマ区切り）」で保存する。
